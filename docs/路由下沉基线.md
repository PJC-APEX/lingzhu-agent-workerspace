# 路由职责下沉：第一批基线

日期：2026-11-12（Asia/Shanghai）。本批建立可回溯的工作区备份和测试、接口基线，不修改生产业务实现，不修复或重建 Git。

## 基线范围

- OpenAPI：36 条路径、41 个 HTTP 方法与路径组合，包含认证及文档端点。
- 完整后端测试：224 条通过。
- 业务数据库内容 SHA-256 与运行前备份一致。
- 测试默认数据库使用内存 SQLite；上传、素材、导出、日志及剪映目录重定向至本次基线目录。
- Python TCP 连接在测试过程中被阻止；Windows asyncio 内部 socketpair 创建例外。该隔离只用于本次测试进程，不是系统防火墙。
- 对象存储使用已有测试夹具的本地实现；模型及投递测试沿用现有替代实现。

## 发现并修正的测试隔离问题

`services/agent_rewrite/service.py` 自行读取模块绑定的 `SessionLocal`，未使用 HTTP 的 `get_db` 覆盖。将默认库隔离为内存库后，`test_stream_never_reaches_a_real_model` 暴露 `no such table: agent_threads`，说明原测试可能误读实际业务库。

只修改 `tests/conftest.py`：在 client 夹具中把该模块的 `SessionLocal` 替换为当前 client 的 `TestingSession`。生产实现不变。修复前 223 条通过、1 条失败，修复后 224 条通过。

另发现 `test_pasted_inline_document_is_an_ordinary_chat_message` 仅替换了文本生成，没有替换两轮意图分类，产生 6 次被拦截的外部连接。为该测试使用已有分类替代辅助函数，固定普通聊天分支；原有消息、上下文和历史断言均保留。此测试验证消息处理，不验证模型分类质量。

首次验证脚本拦截了 Windows asyncio 建立内部 socketpair 所需的本机 TCP，导致 142 个 setup 错误。这是验证脚本问题，不计为项目失败；修正后重新执行完整测试。

## 产物与复现

运行：

```powershell
.\.venv\Scripts\python.exe scripts/capture_refactor_baseline.py
```

每次运行生成独立的 `recovery-backups/baseline-时间戳/`：

- `workspace-and-git.zip`：运行前工作区与现存 Git 元数据；排除依赖、构建目录、旧备份及测试缓存。
- `backup-manifest.json`、`backup-checksum.json`：文件及备份 SHA-256；ZIP 完整性已检查。
- `openapi.json`、`endpoints.json`：结构和接口清单。
- `pytest-results.xml`：完整后端测试结果。
- `network-attempts.json`：被阻止的连接及所属测试。
- `summary.json`：退出码、接口计数、数据库/源码一致性检查。

备份包含本地环境配置与数据库，仅用于本地恢复，已加入 `.gitignore`，不应上传新仓库。

## 后续对比及验证边界

后续每批使用本批的 OpenAPI 与 HTTP/SSE 行为测试作对照；接口数量本身不能证明兼容。OpenAPI 对无 response_model 的返回体及 SSE 事件描述不完整，应保留已有响应、权限、幂等与错误事件断言。

本批未验证真实模型、OSS、Redis、PostgreSQL 和真实剪映桌面链路，也未执行人工 UI 主流程；224 条通过不能替代这些集成验证。前端构建留待最终验收。

Git 提交历史仍损坏；ZIP 保留现状供恢复，不代表历史对象已找回。
