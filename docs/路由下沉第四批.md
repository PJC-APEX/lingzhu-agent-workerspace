## 事务和事件

API 层继续持有 get_db 依赖并传递给应用用例；没有在 API 中提交或修改 ORM 模型。HTTP 租约继续覆盖整个请求/流生命周期。

流式用例返回普通事件字典，结束标记为 None；只有 API 编码 `data: ...` 和 `[DONE]`，状态码、响应头、事件字段与顺序保持原契约。成功/失败重放不再次执行图、不重复保存用户消息。

写入失败由应用入口回滚。保留确认卡与素材先提交、然后恢复图的原有事务边界，不引入数据库/检查点跨系统事务。旧确认建任务与 Outbox、关联 action、助手消息仍同事务提交，提交后投递；投递异常时保持 queued 和 pending Outbox，以及原来的提示字段。

## 发现并修正的旧缺陷

1. 未传 requestId 时，原路由与 prepare_turn 各生成一个 ID，导致 SSE/日志与数据库轮次记录不一致。现在一次生成并传入 prepare_turn；新增测试验证 SSE、图调用和数据库 ID 相同，不改变请求指纹字段。
2. 模型失败处理读取 `ModelCallError.message`，但该异常类没有保存 message，导致错误分支再次抛 AttributeError。新增失败重放测试先失败，再为异常类补齐已有调用方需要的 message 属性；失败轮次现在能保存并输出错误事件，重放时不重新执行。
