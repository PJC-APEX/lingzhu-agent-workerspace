## 四、清单中发现的额外问题（供决策，不强制）

### 1. 端点数量说明

经精确统计，`@router.*` 装饰器共 **37 个**。同名路径出现两次的（`/workspaces`、`/workspaces/{id}/documents`、`/rewrite-sessions/{id}`、`/agent/prompts`、`/agent/threads/{id}/messages`）都是**同一路径配不同 HTTP 方法**，属正常设计，不是重复定义。

`/assets/{id}/review` 在全文件中只有 1 处（1541 行），首轮提到的"1389 行残留"经核对不存在，特此更正。

### 2. 两个对话端点并存

- 944 `POST /messages` → 走 `agents/graph.py`（86 行的简易单节点图）
- 1065 `POST /messages/stream` → 走 `graph/graph.py`（真正的 LangGraph 主流程）

两条链路都能写消息、都在改 `thread.title`，但不共享任何代码。这正是"`agents/` 与 `graph/` 职责重叠"的具体体现。拆分时应明确保留一条。

### 3. 编码乱码

以下位置的中文已损坏（`宸ヤ綔鍖?`、`瀛楀箷鏂囦欢涓嶈兘瓒呰繃 10MB` 等），说明文件经历过一次错误的编码转换：

- 125、176、231 行：`_get_or_404(db, Workspace, workspace_id, "宸ヤ綔鍖?")`
- 156、182、198、216、219、258 行：日志与报错文案

这些乱码会直接出现在 API 报错响应里给最终用户看。

### 4. N+1 查询

`get_documents`（467 行）：for 循环内逐条查版本。文档数 50 时就产生 51 次查询。同理 `get_workspace_jobs` 虽未循环查询，但也没做分页（固定取 50 条）。

### 5. 手工开库（最重要）

`get_session_factory()()` 出现在 124、151、175、194、230 行。同一请求流程里，路由持有 `db` 的同时又开了第二条连接。并发下可能出现同一事务两次快照、看不到彼此未提交的写入。**建议这一项在拆分时顺手一并规范。**

## 五、建议执行顺序

按"风险从低到高、收益从大到小"排序：

| 步骤 | 动作 | 风险 | 说明 |
|---|---|---|---|
| 1 | 抽出 `deps.py` / `schemas.py` | 极低 | 纯搬移，不改逻辑 |
| 2 | 拆 prompts.py、jobs.py、media.py | 低 | 依赖少、逻辑薄 |
| 3 | 拆 documents.py、workspaces.py、subtitles.py | 低 | 拆的同时顺手修手工开库 |
| 4 | 拆 rewrites.py | 中 | 6 个端点共享 `_session_payload` 等 3 个工具函数 |
| 5 | 拆 assets.py | 中 | download 含临时文件与 zip，需细测 |
| 6 | 拆 agent.py（再分 stream / actions） | 高 | 271 行 SSE 函数，涉及幂等与状态恢复 |
| 7 | 清理重复端点、统一对话通道 | 中 | 需先确认前端调用情况 |

每步完成后跑一次 `pytest`，全部通过再进下一步。第 1-2 步几乎零风险，可以立刻开始。
