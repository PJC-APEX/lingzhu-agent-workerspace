# 第五批：认证、租约依赖与显式路由装配

## 完成范围

- `api/v1/auth.py`：注册/登录/登出/me 的 HTTP 适配、邮箱入参校验和 Cookie 设置/删除。
- `api/v1/origin.py`：Origin、Host 和 Sec-Fetch-Site 检查，保留原有允许来源及 403 文案。
- `application/auth_service.py`：用户注册、密码验证协调、会话签发、认证、过期会话删除和登出；不依赖 Request/Response。
- `services/auth_crypto.py`：原 PBKDF2-SHA256（600000 轮）与令牌摘要算法，纯函数。
- `repositories/auth_repo.py`：用户和会话存取，无事务提交。
- `core/identity.py`：上下文身份读写，不依赖 HTTP；图节点不再导入认证路由/服务。
- `application/thread_execution.py` 与 `repositories/thread_lease_repo.py`：租约归属、原子认领、续租、释放及后台等待。HTTP 租约依赖移至 `api/v1/deps.py`，保留请求/流生命周期中的释放。
- `api/v1/deps.py`：认证与租约适配；认证在线程池内部使用自己的短会话，不跨线程传递请求 Session。
- agent/assets/exports/jobs/rewrite/documents/auth/health 各自拥有独立 APIRouter；`routes.py` 显式组合，main 只 include 汇总 router。删除依靠共享 router 和导入副作用的 `common.py`。
- 任务路由直接引用 application 图恢复和 infrastructure 发布入口，不再从 worker 导入私有回调。
- 原 `services/job_queue.py` 的 Outbox 写入实现逐字节移到 `repositories/outbox_repo.py`，所有调用方更新导入，无重复实现。
- 删除旧 `services/auth.py`、`services/thread_execution.py`；没有保留旧路径兼容分支。
- 测试夹具直接配置容器和 app.state 的工厂引用，移除多层 `_TestingState` 代理，并以 finally 保证清理。

## 兼容性

保留认证接口路径/方法/状态码、错误文案、30 天会话、HttpOnly/SameSite=lax/Path=/、HTTPS 或 AUTH_COOKIE_SECURE 控制 Secure 的规则、Cookie 名和密码/令牌编码。

过期会话先删除并提交，再返回原 401；注册过程中用户已 flush 而会话创建失败时回滚用户。业务请求继续验证来源、在整个依赖生命周期中设置/重置用户 ContextVar。

租约保持原 900 秒期限、30 秒心跳、执行令牌条件写入、旧持有者不能释放新持有者租约；没有扩大修改任务执行/Outbox 状态机的并发策略。
