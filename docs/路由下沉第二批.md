# 第二批：工作区、改写与提示词职责下沉

## 完成范围

`api/v1/rewrite.py` 从 398 行的业务实现改为参数解析与应用用例调用，保留原有 16 个端点、Pydantic 入参及函数名。该文件不再直接查询/写入数据库、提交事务、校验版本、生成候选或管理提示词版本。

- `application/workspace_service.py`：创建和列出工作区，控制创建事务。
- `application/rewrite_service.py`：创建/读取改写会话、切换对比基准、保存工作版本、全文/选区改写、多候选和候选选择；控制提交与回滚。
- `application/rewrite_commands.py`：普通数据类输入，应用用例不接收 FastAPI/Pydantic 请求对象。
- `application/rewrite_access.py`：显式用户归属检查，服务调用不依赖 HTTP ContextVar。
- `application/rewrite_snapshot.py`：复用原快照，补齐与旧路由相同的各版本归属检查；文档更新用例也使用这一份快照。
- `application/prompt_service.py`：提示词选择、默认版本解析与版本管理；图调用方保留原 ValueError 约定，HTTP 用例映射业务异常并控制事务。
- `application/model_catalog.py`：模型与预设目录，原返回结构不变。
- `repositories/rewrite_repo.py`、`workspace_repo.py`、`prompt_repo.py`：承接数据访问，不提交事务。
- `services/agent_prompt_library.py`：只保留默认数据、结果数据类与序列化，无 Session 或数据库查询。

迁移了现有模型调用测试的替换位置：改写测试替换 `application.rewrite_service.run_normal_rewrite`，提示词降级测试替换新的应用层解析器；不为旧测试增加生产代码兼容分支。Agent 现有解析调用同步切换到应用层。

## 行为与边界

保留 HTTP 状态、错误文案、字段、UTF-16 选区转换、候选拼接、版本父子关系、模型调用及现有日志事件。未调整现有版本并发策略，也未修改模型算法。

归属查询仍检查原文、原文版本、会话、工作版本及改写记录的工作区属主，不能仅凭一个可信会话就信任所有关联版本 ID。

应用层在写入异常时显式回滚。新增测试通过在工作版本已 flush 后使改写记录写入失败，验证版本与当前指针一起回滚；也验证提示词版本写入失败不会留下孤立的预设。
